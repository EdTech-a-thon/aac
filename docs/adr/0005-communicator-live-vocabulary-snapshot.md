# Communicators consume a live Vocabulary snapshot

The AAC app must read the live Vocabulary without exposing Initial Snapshot or Change Set history, and we will soon want an offline cache of that same read. Opening a Vocabulary loads one snapshot into memory: Vocabulary name, Palette, Boards (including Buttons outside the viewport), Buttons (label, unset/binding/custom color, Action), and a revision (tip Applied Change Set sequence, or 0). Home Board is derived from that snapshot by the glossary rule, not stored as an id. A future cache persists that same document; v1 is online-only and refetches on each open. Replaying Applied Change Sets on device was rejected because Communicators must not see history and the cache should be what we render. Fetching Boards and Buttons as separate resources was rejected because a cache of many partial reads is harder to keep coherent than one snapshot. Pre-resolved hexes-only was rejected because the cache would be a picture, not the live Vocabulary.
